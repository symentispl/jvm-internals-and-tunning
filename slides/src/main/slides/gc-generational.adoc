* age >= *tenuring threshold* (or survivor space full) => *promoted* to Old

=== Object age

* age is stored in the object header (*mark word*, 4 bits => max 15)
* every young GC an object survives: age + 1
* the JVM adapts the threshold at runtime (survivor space occupancy)
* promoting too early ("premature promotion") fills Old with short-lived garbage

=== Object header

[mermaid,format=svg]
----
packet-beta
  0-1: "lock"
  2-2: "-"
  3-6: "age"
  7-37: "identity hash (31 bits)"
  38-63: "GC bits / unused"
  64-95: "klass ptr (4 B)"
  96-127: "fields ..."
----

* *mark word*: identity hash, GC *age*, lock state, GC marks / forwarding pointer
* *klass pointer*: the class of the object (tells GC the object layout)
* *compressed oops*: 32-bit references (shifted by 3) for heaps < 32 GB
* JDK 25: *compact object headers* (`-XX:+UseCompactObjectHeaders`, JEP 519) merge both into 8 B, up to ~20% less heap in benchmarks, opt-in

* solution: remember every old->young pointer, *remembered set*

* heap split into 512 byte *cards*, one byte per card in the card table
* young GC scans only *dirty* cards of Old, then cleans them

=== Post-write barrier

Every reference store marks its card dirty

[source,java]
----
obj.field = ref;        // application code
----

[source]
----
store obj.field, ref    // JIT emits
CARD_TABLE[obj_address >> 9] = DIRTY
----

* ~2 extra instructions per reference store
* *conditional card marking*: check if already dirty before writing, avoids cache line contention between threads (`-XX:+UseCondCardMark`)
