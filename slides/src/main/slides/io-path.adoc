=== Reading a file, the simple way

[source,java]
----
var file = new File("geecon.json");
try (var input = new FileInputStream(file)) {
  byte[] buff = new byte[512];
  int fileSize = 0, buffSize;
  while ((buffSize = input.read(buff)) != -1) {
    fileSize += buffSize;
  }
  out.println(format("file size is = %d", fileSize));
}
----

=== File vs Path

* `java.io.File` is a legacy *path name*, it is not an open file
* `java.nio.file.Path` + `Files` is the modern API (Java 7), better errors and attributes
* the file is opened by the *stream or channel* constructor, not by `new File()`

* an *fd* is a small integer: an index into the process table of open files
* two fds can share one open file description (and its offset)

=== FileDescriptor in Java

* `java.io.FileDescriptor` wraps the integer fd
* one `FileDescriptor` can be shared by several streams and channels
* the fd is closed when the *last* user closes it, or when a `Cleaner` runs after GC (finalizers are no longer used)
* always close files explicitly: try-with-resources

* the *GC may move* a heap array at any time, the kernel needs a stable address
* so `GetByteArrayRegion` copies the data to a native buffer first
* buffer up to 8 KB: on the C stack, above: `malloc` + `free` on every call

=== NIO: direct buffers

[mermaid,format=svg]
----
flowchart LR
  subgraph DB["write(directBuffer)"]
    direction LR
    d1["direct buffer<br/>(native memory, never moved)"]:::y --> k2["write()"]:::r
  end
  subgraph HB["write(heapBuffer)"]
    direction LR
    h1["heap buffer"]:::g -- "copy" --> t["temp direct buffer<br/>(thread-local cache)"]:::y --> k1["write()"]:::r
  end
  classDef g fill:#a5d6a7,stroke:#2e7d32,color:#000
  classDef y fill:#fff59d,stroke:#f9a825,color:#000
  classDef r fill:#ef9a9a,stroke:#c62828,color:#000
  classDef n fill:#eeeeee,stroke:#9e9e9e,color:#555
----

* `ByteBuffer.allocateDirect()` lives in native memory (outside the Java heap), the GC never moves it
* with a *heap* buffer, NIO copies to a cached temporary direct buffer
* direct buffers are expensive to allocate and free: reuse them
* the size of the thread-local cache is limited by `jdk.nio.maxCachedBufferSize`

=== What the OS sees

 openat(AT_FDCWD, "geecon.json", O_RDONLY) = 4
 fstat(4, {st_size=...})                   = 0
 read(4, "...", 512)                       = 512
 read(4, "...", 512)                       = 512
 ...
 close(4)                                  = 0

* one system call per `read()`: user space -> kernel switch every time
* `read(512)` over a big file = a lot of system calls
